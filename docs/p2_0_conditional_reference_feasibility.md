# P2-0：Conditional Reference Selection 最小可行性研究

日期：2026-11-10。结论：**INSUFFICIENT EVIDENCE**。

合法状态具有部分优势预测信号，但简单规则尚未在录制隔离交叉验证中同时保留原训练分布精度并稳定取得开发来源收益。更关键的是，端点优势几乎完全与训练/新开发集合重合，尚不能证明需要一个可学习的、跨来源有效的条件机制。本轮没有训练门控网络，没有改变FLASH参数或架构。

## 冻结假设与数据权限

可证伪假设：合法当前反馈与8帧测量历史可决定何时选择D0/D3，超越固定融合并保留原分布精度。只验证离线动作预测，不对应实机成功率。

输入为已封存的Step8000 FP32冻结预测：P1-5 B0/B2 Step0导出中仅取97个训练recording×5窗；P1-7 D0/D3中仅取4个development_success recording×5窗。共101来源、505窗，**不是旧P0的505窗集合**。旧候选4来源20窗和此前6个锁定测试来源30窗均排除。读取器仅反序列化允许的NPY行；完整文件字节哈希只校验封存完整性，不计算排除行的动作、状态或指标。`results/identity.json`记录允许行、排除来源、seal及数值排除计数0。读取元信息识别角色和执行分组是审计操作，角色、来源ID、成功标签不进入选择器。

原模型已训练过这97个来源，其结果只是训练来源保留能力诊断。4个开发录制已用于本次研究，不能再作为最终独立测试。此前6来源的P1-7确认性证据不重评，也不调参。本轮未获得额外未参与设计的新成功录制；P2最终测试仍缺数据。

继续复用既有动作契约：Absolute物理rad，canonical58为左臂[0:7]、左手[7:29]、右臂[29:36]、右手[36:58]；history[-7,0]、扩展监督[-2,51]、评价[0,49]。D0/D3各自先按原路径恢复Absolute动作，然后融合；从不在不兼容的归一化空间中直接加减q0，不插值历史坐标。所有有效掩码为真，GT/当前状态/历史逐元素配对核验。

身份：研究基线提交`516d87a`；上游只读FLASH快照`d208d414efbb78483f44bfef4c2a9314115dd632`；Step8000参数SHA256 `40b2c2c4dcdd6fb88dd847d5762d2071fba5028af0942c6dfe457409fe5f5919`；匹配统计SHA256 `a5d7bd2dd422148736c69f1bf52a721d5770ba810f3bace9a2dd413395544d52`。原始数据、权重、训练仓库均只读。

## 预先固定的简单规则与划分

在读取预测前写入`results/analysis_plan.json`，以下规则未根据结果调整：

- 输出混合：Aλ=A_D0+λ(A_D3−A_D0)，每个50×58 Chunk共享单个λ；固定网格0、.25、.5、.75、1。
- 全局状态距离：当前58D反馈相对训练折均值的RMS z-score；各关节标准差下限.05 rad。
- 最近邻距离：同样标准化状态相对训练折参考窗口的最小RMS距离。
- 历史运动：8帧测量历史的相邻差，按同一标准差缩放后的RMS。
- 无监督规则：高于训练折标定得分q99时选D3，否则D0。只使用合法输入，不使用GT定阈值。
- 监督阈值规则：固定为高分选D3；仅在拟合折中以GT构造两分支窗口MSE，最小化来源/集合平衡的目标，并约束拟合折训练RMSE不高于D0的1.1倍。允许退化为始终D0，不搜索反向规则。

4折：每折留出1个开发recording与24/25个训练recording，整段recording一起划分；其余3开发来源和72/73训练来源用于拟合。采用固定种子20261110哈希分组。阈值拟合时两个集合各占1/2，每集合内recording等权、recording内窗口等权。计算训练标定得分时，训练参考库连同均值/标准差排除整个自身recording，避免最近邻自匹配；验证得分只用该折拟合参考库。没有窗口级随机拆分，没有把高度相关窗口作为IID样本算置信区间。各来源同为5窗，因此当前集合内窗口合并MSE等于等权来源MSE，合并RMSE并非来源RMSE的算术平均。

探索性联合验收标准：训练OOF RMSE及P99不超过D0的1.1倍，>0.5 rad元素不增加；开发OOF RMSE至少降低10%，且至少3/4来源改善。10%只是本轮预先固定的工程保留/收益预算，不是统计显著性标准，更不能据此证明CRS不可能。即使通过，也须检查局部动态与集合身份混淆。

## Oracle空间与可学习性

窗口端点Oracle使用未来GT，仅是离线标签/参考上界，不能在线使用。训练485窗中只有1窗偏好D3，开发20窗全部偏好D3；来源平均上97/97训练来源偏好D0，4/4开发来源偏好D3。只有1个训练来源同时具有两种窗口标签，开发来源没有窗口内标签切换。

如果直接用禁止作为在线输入的集合身份进行离线控制“训练选D0，开发选D3”，其结果与来源级端点Oracle完全一致。训练窗口Oracle MSE为0.0000972915，来源Oracle为0.0000973499，仅差约0.0601%；开发窗口/来源Oracle完全一致。这说明现有端点监督几乎不要求学习来源内部的条件选择，不能排除学到的只是集合识别。

端点Oracle并不是所有凸融合的上界：两端误差可抵消。单独给出每窗解析连续Oracle λ*=clip(−〈e0,d〉/〈d,d〉,0,1)，其中e0=D0−GT、d=D3−D0。连续Oracle训练RMSE=0.009619、开发=0.101203；与端点Oracle相比增量有限。该λ也使用未来GT，绝不进入推理。本轮不将Oracle挑选后的结果描述为可部署方法。

状态信号不是完全没有关联：OOF全局距离/最近邻/历史运动的端点优势AUC分别约0.704/0.860/0.676；与MSE优势的相关分别0.180/0.395/0.141。减去每recording均值后的相关约0.168/0.408/0.110，表明最近邻距离与优势大小存在描述性关联，不能一概归为纯ID。但几乎没有来源内部端点标签变化，且规则存在假阳性和漏检，这些相关并不能证明跨录制选择可学习。AUC基于21个D3标签对484个D0标签，窗口相关性强，不报告IID显著性。状态分数区间明显重叠，全局状态距离甚至不能覆盖全部新开发来源。完整范围见`report_final/feasibility.json`。

因此不实现MLP或视觉门控：数据尚未支持超越集合身份的稳定决策，当前也没有足够开发recording验证更复杂门控。**这是否定现有证据充分性，不是证明未来CRS无效。**

## 计算成本：真实GPU测量

在无训练任务的空闲GPU上，使用一个允许的开发窗口重新加载同一Step8000完整参数，原FLASH推理路径FP32/highest、确定性XLA、Batch1、1次flow速度计算。没有读取此前6测试来源的数值。每项3次预热、20次同步计时，排除JIT编译和CPU图像读取。设备RTX PRO 5000 72GB Blackwell，JAX0.5.3。

共享前缀后的双分支比D0约增加2.85%，朴素双调用约增加101.82%。仍有2次Expert速度前向，不能称为单次Expert推理，也不能从时间直接推出FLOPs翻倍：VLM占主要耗时。两分支复用同一份模型参数，无第二个独立Expert；新增可训练参数0。当前规则仅存训练折均值、尺度和至多365×58参考状态，不超过21286个浮点数；计分复杂度O(58×参考窗口数)，并含8×58历史差计算。CPU三项分数一起计时中位数0.02648 ms、P95 0.04331 ms，不含数据传输。标量阈值在Expert前即可选一个分支；0<λ<1的物理融合则必须取得两分支结果。

GPU所有编译变体累计peak_bytes_in_use=27,729,289,728（约25.82 GiB），不是单一部署路径显存峰值；没有硬件FLOP计数器测量。重新推理与封存D0/D3以及共享前缀路径的最大逐元素差均为3.5763e−7 rad，低于1e−5；Checkpoint文件清单未变。详见`benchmark.json`和日志。

这些时延不能满足逐帧33.3 ms重新推理预算；滚动Chunk、异步执行及机器人链路未测试，不能默认符合30 Hz部署。本轮完全离线，无机器人控制。

## 决策与下一步

1. 固定融合：预设网格不足以同时保留和改善；小连续权重的有限折衷仍未排除。
2. 可观测条件：最近邻状态有部分相关信号，但OOF规则不能稳定满足目标，无法识别一个明确受益来源。
3. 小型CRS：未训练，没有优于简单规则或固定融合的证据。
4. 原分布精度：当前条件规则未完全保留，最近邻仍产生约11% RMSE代价。
5. 尾部与局部动态：开发尾部降低但训练Max增加；形状/变化误差基本没有改善，不能称可靠性问题已解决。
6. 身份混淆：现有端点标签几乎等同于集合身份；recording隔离CV可以防直接来源泄漏，却不能消除集合/采集条件混淆。
7. 方法设计：现阶段不建议改Transformer内部结构，也不建议以本轮数据训练更复杂门控。

下一步只建议一个最小实验：先补充**状态范围交叉覆盖、来源隔离的新成功录制**，在探索集上预先固定一个保守状态距离选择规则，与D0、D3和小固定权重融合进行按recording验证；只有同类状态下出现可重复的分支优势变化且有保留精度收益，才启动轻量chunk级门控。若优势仍仅按集合划分或简单融合已足够，则否定“需要条件门控”的必要性。最终另锁未参与本轮及下一轮设计的新成功recording，在规则/模型冻结后只评一次。失败示范另列，不混入成功指标。

本轮结论：**INSUFFICIENT EVIDENCE**。没有新增Action Expert、没有GPU训练、没有改动外部训练工程/数据/权重、没有推送远端。
